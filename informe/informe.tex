\section{Introducci\'on}

Este proyecto cubre la especificaci\'on del Proyecto Parcial 2: una aplicaci\'on con frontend y backend, pruebas de extremo a extremo con Playwright, un pipeline de GitHub Actions que solo despliega en AWS EC2 cuando las pruebas aprueban, e instrumentaci\'on OpenTelemetry hacia OpenObserve (registros, m\'etricas, trazas y recursos del servidor).

La base visual es UTEQGram, la PWA de la materia de aplicaciones web progresivas. Esa versi\'on era est\'atica, usaba Supabase para el feed y no ten\'ia login. En esta entrega se recortaron Firebase, el Service Worker y las claves de Supabase. Se a\~nadi\'o un API en Node.js con SQLite, autenticaci\'on JWT en cookie httpOnly y dos roles: \texttt{user} (feed de posts) y \texttt{admin} (CRUD de usuarios).

\section{Objetivo}

Implementar un flujo de integraci\'on y despliegue continuo hacia EC2, condicionado a Playwright, con observabilidad centralizada en OpenObserve. La aplicaci\'on debe exponer login, posts y administraci\'on de usuarios sobre SQLite, de modo que las trazas cubran petici\'on HTTP y consulta a base de datos.

\section{Arquitectura}

El Compose de EC2 levanta cuatro servicios: \texttt{uteqgram} (Express + SQLite + archivos de imagen), \texttt{otel-collector} (OTLP y scrape de Prometheus), \texttt{node-exporter} y \texttt{openobserve}. La aplicaci\'on exporta OTLP a \texttt{http://otel-collector:4318}; el collector reenv\'ia a \texttt{http://openobserve:5080/api/default} con autenticaci\'on Basic.

Los datos viven en un volumen Docker (\texttt{/data/app.db} y \texttt{/data/uploads}). El frontend Material se sirve desde \texttt{public/}. Las rutas HTML aplican la misma pol\'itica que el API: sin sesi\'on se redirige a \texttt{/login}; un \texttt{user} que pide \texttt{/admin/users} vuelve al feed.

\section{Pruebas automatizadas}

La suite se ejecuta con \texttt{npx playwright test}. Un servidor ef\'imero (\texttt{tests/start-e2e.js}) borra \texttt{data/e2e.db}, siembra admin/user y tres posts, y desactiva OpenTelemetry para no depender de OpenObserve en CI. Hay \textbf{200 pruebas} en ocho archivos: login UI, feed, CRUD de usuarios, contratos de API, cat\'alogos masivos y 15 defectos documentados con \texttt{test.fail()} para no tumbar el deploy.

En GitHub Actions el job Playwright del run 3 termin\'o en verde (6~min 47~s). El job \texttt{notify} envi\'o el resultado al stream \texttt{cicd} de OpenObserve. El job SSH no corre si Playwright falla: el run 2 (t\'itulos duplicados / suite incompleta) lo demuestra, porque el despliegue ni siquiera se program\'o.

El criterio de aceptaci\'on del commit con error intencional se cubre con ese mismo dise\~no: alterar un texto visible o el \texttt{status} de \texttt{/api/health}, hacer push a \texttt{main}, observar Playwright en rojo, el evento \texttt{ci\_test/failure} en OpenObserve y la ausencia del job SSH. Un commit v\'alido deja Playwright en verde y, con la clave SSH correcta, actualiza los contenedores y registra \texttt{event=deploy}.

\section{Observabilidad}

Cada petici\'on HTTP escribe un log JSON con \texttt{timestamp}, \texttt{level}, \texttt{msg}, \texttt{route}, \texttt{statusCode}, \texttt{durationMs} y \texttt{traceId}. Las m\'etricas \texttt{http.server.duration} y \texttt{http.server.requests} etiquetan m\'etodo, ruta y c\'odigo. Los accesos SQLite abren un span \texttt{sqlite.query*} con \texttt{db.statement}. En OpenObserve hay cientos de trazas del servicio \texttt{uteqgram} y el stream \texttt{cicd} con \texttt{success} y \texttt{failure}.

El tablero \textit{UTEQGram --- Infraestructura y CI/CD} grafica CPU, RAM, bytes RX/TX y temperatura. \texttt{/api/host} expone los mismos valores. En EC2 virtualizada el sensor \texttt{/sys/class/thermal} no publica grados reales (\texttt{thermalAvailable=0}); \texttt{node-exporter} s\'i exporta \texttt{node\_hwmon\_temp\_celsius} (en esta instancia el NVMe reporta $-273{,}15\,^{\circ}$C, es decir, sin lectura f\'isica). No se inventa un valor de temperatura.

Las alertas operativas \texttt{ram\_alta\_ec2}, \texttt{errores\_http\_app} y \texttt{pipeline\_ci\_fallido} viven en Reliability. Esta \'ultima qued\'o en estado \textit{Firing} porque el stream \texttt{cicd} contiene al menos un \texttt{status=failure}.

\section{Conclusiones}

UTEQGram dej\'o de ser una PWA acoplada a Supabase y pas\'o a un backend propio con SQLite, roles reales y un pipeline que bloquea el SSH a EC2 si Playwright falla. OpenTelemetry y OpenObserve cubren logs, m\'etricas, trazas, el registro del CI, un tablero de infraestructura y alertas operativas. La temperatura del hypervisor de EC2 es una limitaci\'on conocida: se grafica la m\'etrica real (incluso cuando el sensor no entrega grados \'utiles) y no se fabrica un valor.

La aplicaci\'on y OpenObserve ya responden en \texttt{3.144.214.32}. El job de pruebas y el de notificaci\'on a OpenObserve est\'an en verde. El auto-deploy SSH queda condicionado a Playwright y a una clave \texttt{EC2\_SSH\_KEY} v\'alida (contenido completo del \texttt{.pem}).
